# ADR-0010: FTP with Pure-FTPd and xcp-ftpauth speaking extauth itself

- Status: accepted
- Date: 2026-11-02
- Amends: 06-service-drivers.md §7 (FTP), 01-architecture.md (`xcp-ftpauth`)

## Context

USR-FTP-01 needs FTP accounts per hosting account: create, delete, change
password, a quota, and a folder they cannot leave. The plan picks Pure-FTPd
with virtual users through its external authentication (extauth) and an
`xcp-ftpauth` handler "backed by the DB". It left open how the handler gets
the logins, how FTP logins are named, and how Pure-FTPd is run on Ubuntu,
whose package starts it through a SysV script and a Perl wrapper.

## Decision

- **Logins are `name@domain`**, with a domain of the account (not a
  wildcard), so they are unique across the server without account prefixes
  and read like the account's mail addresses. Removing the domain removes its
  FTP logins. Each login has a folder inside the account's home (the whole
  home by default), an optional quota, and an Argon2id password hash made by
  xcp-api, the same format as mailboxes (ADR-0007).
- **Fragments, like mail:** `FTPAccountApply` gives the agent all logins of
  one account; the agent creates missing folders as the account's user
  (through fsx, beneath the home), refuses a login another account's
  fragment has, and writes `/etc/xcp/ftp/accounts/<user>.json` (root only)
  with the uid, gid and absolute folders it found itself. A suspended
  account's fragment has no logins; suspension also kills the user's
  processes, which ends its FTP sessions.
- **xcp-ftpauth implements the extauth socket protocol** (the request lines
  `account:`, `password:`, … `end`; the reply `auth_ok:`, `uid:`, `gid:`,
  `dir:`, `user_quota_size:`, `end`) instead of running under `pure-authd`,
  which would fork a process per login. It is a small daemon (unit
  `xcp-ftpauth.service`) running as root without any capability, with no
  network and a read-only system; its socket is in `/run/xcp-ftpauth`, which
  only root can enter. It reads the fragments again when the folder changes,
  checks passwords with at most four Argon2id checks at a time (each costs
  64 MB), answers unknown logins after a dummy check so timing does not tell
  which logins exist, and opens the login's folder with fsx beneath the
  account's home at every login, so a folder the user replaced with a
  symlink is refused rather than becoming the chroot.
- **Pure-FTPd from Ubuntu, run by XCP's own unit:** `pure-ftpd.service` in
  `/etc/systemd/system` (it overrides the one systemd generates from the
  SysV script) starts `/usr/sbin/pure-ftpd /etc/pure-ftpd/xcp.conf`.
  Everyone is chrooted, anonymous FTP and system logins (PAM, unix) are off,
  only UIDs 10000 and up may log in, passive ports are 30000–30999, and
  explicit FTPS is offered with the host name certificate (the panel's
  self-signed pair before AutoSSL has one; installing the host certificate
  re-renders the file and restarts Pure-FTPd). `openbsd-inetd`, which the
  package pulls in, is disabled when the installer installs Pure-FTPd.
  Transfers are logged in xferlog format for bandwidth stats later.

## Consequences

- No database access and no network in the authentication path; a lost
  fragment can be rebuilt from the panel database by applying the account.
- Between the folder check and Pure-FTPd's chroot the account's own user
  could still swap the folder; that only gives the login what the account
  user can do anyway.
- Sessions of a deleted login or after a password change keep running until
  they end; listing and ending sessions is USR-FTP-02 (P2). FTPS stays
  optional until USR-FTP-03 (P2) adds a switch to require it.
- Ports 21 and 30000–30999 must be open; the firewall manager (later)
  opens them.
