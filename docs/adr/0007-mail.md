# ADR-0007: Mail with Postfix, Dovecot and Rspamd; maps built by the agent

- Status: accepted
- Date: 2026-11-01
- Amends: 06-service-drivers.md §4 (Mail)

## Context

P1 mail part 1 needs mailboxes with quotas and per-mailbox switches,
forwarders, a default (catch-all) address, DKIM/SPF/DMARC with a check
and repair per domain (USR-MAIL-01, 03, 06, 09), and server settings
(ADM-MAIL-01). Postfix maps are global files, while the panel changes one
account at a time; Dovecot needs a password per mailbox; DKIM needs keys
per domain. The plan left the map format, password scheme and signer open.

## Decision

- **Packages:** Postfix, Dovecot (IMAP, POP3, LMTP) and Rspamd from Ubuntu,
  with Redis for Rspamd's greylisting. XCP owns `main.cf`, `master.cf`,
  `dovecot.conf` and Rspamd's `local.d` files; they are rendered from
  typed settings (ADR-0004), not edited in place.
- **Per-account fragments, global maps:** `MailAccountApply` gives the agent
  everything of one account's mail; the agent keeps it as a fragment
  (`/etc/xcp/mail/accounts/<user>.json`, root only), refuses a domain
  another account's fragment has, and rebuilds the global maps from all
  fragments: Postfix `texthash:` maps in `/etc/postfix/xcp/` (no
  `postmap` step), Dovecot's passwd-file, and Rspamd's DKIM keys. Postfix
  reloads only when a map changed; Dovecot and Rspamd re-read their files.
- **Delivery and storage:** Postfix hands mail to Dovecot over LMTP. A
  mailbox lives in `/home/<user>/mail/<domain>/<local>/Maildir`, owned by
  the account's Linux user, so the account's disk quota counts it; its own
  quota is Dovecot's quota plugin. Deleted mailboxes leave their files, as
  deleted domains do.
- **Passwords:** Argon2id (`{ARGON2ID}`, libsodium's interactive cost),
  made by xcp-api; only the hash reaches the agent. Dovecot caches
  successful logins, so mail clients do not pay the cost on every check.
- **Switches:** login off is Dovecot's `nologin`; receiving off rejects the
  address at RCPT; sending off rejects the login at submission. Users may
  send only as their own address (`reject_authenticated_sender_login_mismatch`).
- **Forwarders** are virtual aliases (a forwarder on a mailbox address keeps
  a copy in the mailbox); a "fail" forwarder rejects with the user's message.
  The default address delivers to a mailbox, forwards, or (by default)
  rejects unknown addresses. Pipes to scripts wait for mail part 2: they
  must run as the account user in its slice.
- **Which domains are local** follows the zone's email routing (P1 #5):
  local and auto-resolving-to-local domains are Postfix's virtual mailbox
  domains, backup MX domains are relay domains, remote domains are left
  out so mail to them goes to their MX. Alias domains map `@alias` to
  `@target`.
- **DKIM:** Rspamd signs outgoing mail with a 2048-bit RSA key per domain
  (selector `xcp`), made by xcp-api and kept encrypted. SPF, DKIM and DMARC
  records come from the zone template and the key; the deliverability
  check compares what public DNS shows with what is expected, and repair
  writes the expected records into the domain's zone when this server
  serves it.
- **TLS** uses the host name certificate once AutoSSL has one, the panel's
  self-signed pair before that; installing the host certificate re-renders
  the mail configs. Per-domain certificates (SNI) come later.

## Consequences

- One account's change rewrites global maps; the fragments make this safe
  and keep each account's data separate, and a lost map can always be
  rebuilt from them.
- No database or socketmap service in the mail path: Postfix and Dovecot
  read plain files.
- Rspamd's other features (spam scores, Bayes) are left at Ubuntu's
  defaults until the spam settings (P2).
